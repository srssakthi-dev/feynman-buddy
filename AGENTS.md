# Project rules

Build the agreed conversational Feynman buddy here. Preserve ../feynman_project. The user chose a new repository rather than a worktree. Do not publish without user authorisation.

Flow: named one-topic session, uploaded ordinary selectable-text notes, RAG-grounded dialogue, then practice reflection. No mandatory numbered headings, reference-point selection, all-point grading per turn, mastery score or rigid taxonomy ladder. Bloom-informed questioning may encourage explanation, application and analysis without classifying learner ability.

Use local models and storage; no paid APIs by default. The template requires integrated audio/image/text models. Captioning must contribute to conversation through reviewed source material. Measure quality and correction burden honestly.

Keep modules understandable. Explain changes concretely. Document scope changes and experimental configurations. Preserve failures and raw results. Do not present software tests as model accuracy, development examples as held-out tests, or planned features as implemented. Never fabricate learner studies or learning gains.

.local/runtime.json and frontend/node_modules reuse installed dependencies initially. Do not mutate shared dependencies or the old project. Create an independent runtime if versions must change. Private data and model caches stay excluded from Git. No delegation requested.
