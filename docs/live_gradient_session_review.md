# Live gradient-descent practice review (28 September 2026)

This is a developer test, not a held-out evaluation or a measured learning outcome. The learner used the two-page gradient-descent development PDF and gave eight responses in session `53d49b8f-d3bf-4969-9fbd-1c830e2fd998`. The original session remains in the local database. Its exported messages, source traces, model timings and reflection were inspected; quoted cases below are from that saved run. Do not count revised prompt checks on this same case as independent validation.

## What worked

The student could teach in free text, receive replies linked to real PDF passages and introduce an uploaded figure within the original topic session. The buddy followed the early explanation of loss and the direction opposite the gradient. It challenged the unsupported global-minimum guarantee in the final student response. The final reflection quoted actual student messages and linked source IDs; it did not issue a mastery grade.

## Observed failures and why they matter

1. **Figure availability:** after “I would like to explain the diagram in the notes,” the buddy said the figure “isn't available here,” even though an image was uploaded and reviewed. The unselected figure was only a candidate; its weak availability instruction let the model mistake its lack of pixels for absence of the image. At that turn the source trace contained only PDF chunks.
2. **Artificial dialogue:** selecting, returning from, and reselecting the figure appended fixed buddy utterances. They were not generated responses to a student explanation. This produced the repeated invitations visible in the conversation.
3. **Overconfident explanation:** the buddy said the algorithm “always steps downhill relative to the current point.” The PDF explicitly says reduction is an objective, not a guarantee for every finite step; an excessive learning rate may increase loss. This is a substantive teaching error, despite having the relevant page in its prompt.
4. **Weak figure evidence:** the BLIP output was “a graph with a curve and a line of the same length.” The learner saved it unchanged (`edited=false`). That caption does not describe the positions or arrow relations, so the model could not independently check the student's reading of A/B. The saved reflection nevertheless referred to “a diagram showing two directions” with this generic caption as its linked source. That is a student report of the image, not visual verification.
5. **Reflection over-attribution:** one observation said the student described landing “on a steep slope” and “before correcting course.” Their quoted words only said overshooting could produce high loss. The extra detail came from buddy turns or inference, not the quoted explanation. Reflection evidence IDs guarantee traceability, not semantic correctness.
6. **Question drift:** the buddy pursued gradient sign flipping and a local minimum after the overshoot discussion. Those details were not established by the uploaded notes or the student's explanation. It also introduced the “uphill” premise before the student had mentioned it, even while citing a relevant page.

The eight recorded Qwen replies took 19.487–51.143 seconds each; the final reflection took 168.086 seconds. Those are single-run local timings, not a latency distribution. Text and speech therefore work as a turn-based study interaction on this laptop, not a real-time spoken conversation.

## Revision made after inspecting this case

`conversation-v3` now asks the buddy to preserve conditional claims and distinguish an intended or local direction from a guaranteed outcome. `figure-available-v3` and `figure-selected-v3` give separate instructions for unselected and selected images. A direct request to explain a figure selects it automatically when exactly one reviewed figure exists, so the same turn receives the figure source. Figure selection and return no longer create pretend buddy messages; the selected image and a neutral invitation appear in the interface. With multiple figures, the learner still selects the intended one. The original v2 prompts and session remain as pre-revision evidence. New traces identify prompt versions and automatic selection.

Software tests after the revision: 45 backend tests passed, four frontend audio tests passed, and lint/build passed. These test routing, preservation and interface construction; they cannot prove that Qwen's mathematical feedback or BLIP's caption is accurate. A single replay with the unselected figure no longer claimed it was absent, but it still failed to request selection. A first selected-figure replay with mixed available/selected instructions told the learner to select the image again. These failures motivated automatic single-figure routing and separate prompts. In the revised selected-figure replay, Qwen replied: “Since the figure is already selected and visible, please describe what you see in it regarding the curve and the line, then connect one of those features to the concept of a parameter update.” Its trace recorded `conversation-v3`, `figure-selected-v3`, and 55.443 seconds. This one exposed development case confirms that specific failure did not recur in that reply; it is not an independent reliability estimate.
